# 可解释规则预警

默认值仅为 Synthetic / 模拟演示配置，不代表企业安全库存或行业标准。无需AI、API或外部服务。当前空间的“运行规则检测”是明确触发动作；刷新页面不自动生成任务或检测日志。

库存/销量和覆盖规则使用已有库存 closing_stock，销售数量使用有效 completed 的quantity。没有在途字段，不加推测在途量。覆盖=周期末库存÷(窗口有效件数/窗口天数)，零销量或记录不足不可计算。库存快照必须在本期末有效，历史更早快照不冒充期末库存。

销售、毛利、广告规则在公司、平台与SKU范围运行；库存仅按共享SKU，退款集中仅SKU，平台退款上升仅平台。没有国家广告归属规则。

看板预警计数和分布按观测期结束日及直接配置的公司/平台/SKU对象筛选，不把公司预警分摊为某SKU。国家、取消订单、平台×SKU联合过滤没有直接配置规则，适用队列为空并提示范围限制；不表示这些维度没有经营问题。

## 窗口与完整性

检测参考日默认上海当前日。结束日取参考日前最后一个有订单记录的日，排除未结束的当天；基期与本期天数相同。需要两个窗口中每个自然日至少有订单记录，缺日则跳过，不填零。不使用月总量直接比较不同天数。这里“完整观测周期”只指日记录连续，不证明外部账本已收齐；期间和账本限制在证据中展示。

基期销售、贡献、ROAS为0或负值时不计算普通下降百分比。毛利率用百分点差；占比上升用百分点差。成本覆盖/质检覆盖变化、广告或确认退款隔离时利润预警跳过并提示先查完整性。没有归因收入或花费不能用店铺销售替代ROAS。12天退款观察未成熟不触发虚假退款率预警。

观测数据可能滞后于检测参考日；预警明确标注历史统计区间和库存快照，不称实时状态。未提供活动日历、全量账单或在途，系统不能证明没上传的数据等于没发生。

## 唯一键、版本与状态

预警唯一键：workspace＋rule_id＋rule_version＋object_key＋首次period_start＋period_end。同周期重复实际运行只更新最近检测时间、次数、当前触发信号，追加检测证据，不重置已解决/忽略状态。相同对象/规则版本跨滚动周期仍未处理时复用开放任务，避免每天创建相同待办；界面周期取最近触发证据，首次周期仍保留。历史周期通过不可变检测记录查找同一任务，回放也不复制任务。问题不再触发时 current_triggered=0，历史任务仍由人处理。已经解决/忽略后新的周期再次触发才创建新任务。

每次检测的证据还记录订单、广告、退款和商品成本的源批次、原始记录及当时已批准修订ID；成本 master 与订单修订可以分别追踪，不用当前新值冒充旧预警计算依据。

配置保存需要修改说明和操作员，产生新版本和不可变快照；旧预警的名称、窗口、阈值、严重程度使用旧快照。新版本同周期可能生成新任务，符合版本唯一键，历史明确可区分。

经营预警状态：待处理、处理中、已解决、已忽略。全部状态操作需要说明，保留原/新状态、操作员与时间，版本锁防止其他会话覆盖。它们与质量异常的确认/驳回/待核实不是同一字段或意义。

每条预警包含发生事项、阈值、对象、周期、公式、当前/基期指标、来源批次/记录、数据限制、排查假设和建议事项；假设不写成确定因果。rule_versions 与 alert_detections 保留配置和重算前证据。

# 本地带凭证数据修订

这是演示级单企业单操作环境流程，申请人/审核人是自报审计标识，不代表可信身份、电子签名或真实角色权限。

1. 在当前数据空间选择原始记录；页面展示当前有效值与已批准版本链。
2. 选择现有非业务键字段，填写新值、原因、凭证编号/本地证据引用，可关联同记录的异常ID。
3. 申请写入 record_revisions：当前有效值、基版本SHA256、变化字段、申请人、时间。待审核不影响任何指标。
4. 审核填写说明，选择已批准或已驳回；只有一次审批。批准前核对基版本哈希，若已有其他版本生效则拒绝覆盖旧基申请，需重新提交。
5. 批准后逐次应用变化得到唯一有效记录，原始 records.raw_json 和原上传文件不变。批准时间单独记录，审批历史不可删除。
6. 在同一事务内重新执行 V1 质检。原值的软规则审核不会自动放行新值，必要时追加“待核实”复审历史。批准非法负价、无效日期、缺失费用等仍会隔离，不因审批绕过规则。
7. 重新打开指标中心即可重算；运行规则检测可重算预警。同周期同规则版本复用预警ID，并追加新的检测证据；不把原记录与新版本同时累计。

批准后的有效版本再次以新CSV/Excel导出重传时，导入器还会对批准后的有效字段指纹去重，避免误建同业务键冲突记录；原始文件重传仍按原始文件/原记录指纹识别，不回退修订。

## 字段范围

允许现有非业务键字段：例如订单quantity/unit_price/discount/sku/date/fee/status，商品unit_cost，退款amount/date/status，广告spend/attributed_revenue，库存四个数量字段。具体列表来自 V1 SCHEMAS 减业务键，不发明字段。

业务键不可修订：orders.order_id；products.sku；inventory.date+sku；refunds.refund_id；ads.date+platform+campaign_id+sku；customers.customer_id。业务键冲突仍全部隔离，本阶段不提供人工选择一份冲突原记录作为赢家。

成本为V1静态成本模型；批准成本修订会重算关联历史样本，不是按日期变动的成本主数据功能。证据引用仅保存用户提供的编号/路径；不声称已验证外部文件真实性或自动读取证明。申请多个字段可通过可测试的 Revisions.request 接口提交同一版本，界面提供单字段申请；库存平衡多字段改动可在代码接口按原模型一起申请。

## 示例

Synthetic-14days.xlsx 中 SYNTH-BAD 的单价为−10，隔离。申请 unit_price=20，原因“模拟录入错误”，证据“Synthetic凭证-001”。批准前公司有效销售1364保持不变；批准后销售1384，记录只计入一个当前版本。库存出库对账可能因新增有效订单而产生差异，必须继续人工核查库存原值，不能偷偷反推库存。

## 审计及安全

record_revisions 保存原值、变化、原因、证据、申请/生效时点、原记录与异常引用；revision_reviews 保存决定/说明/操作员；operation_logs 保存申请/批准动作。历史审批、已批准/已驳回版本不可覆盖。事务失败整体回滚，未批准申请不会出现在有效计算视图。

# V2.1 经营日报产品设计

日期：2026-10-15。状态：设计完成，尚未开发。当前已验收基线为147项测试通过及质量报告浏览器验收通过。

## 目标与范围

新增“经营日报”入口，为模拟运营人员回答：所选经营日表现如何、相比前一日如何、有哪些已记录的规则证据值得核查。

全部结果明确基于Synthetic模拟业务场景及当前导入数据，不虚构真实企业收益。不调用AI、不新增阈值或预警规则、不创建新审批流程、不增加数据库表。首版为按需查看及下载，不定时发送，不保存日报快照。

重要事实：预警按规则自己的window_days计算，订单和库存规则可能使用不同的最新有效观测日。无可用观测日期时run会直接返回，未必产生操作日志；alert_detections主要保存触发证据。现有结构不足以证明任意日期、规则和对象均已完整检测。

## 页面结构

### 1. 日报范围

- 数据空间、经营日期D、对比日期D-1、退款观察截止日H、生成时间。
- 全部时间按Asia/Shanghai展示。默认D为当前空间最近一个早于今天的可定位订单日；没有日期时使用昨日并显示空库或不足状态，不能自动填充数据。
- 日期只允许已结束日期。默认H为今天，允许在D至今天之间选择，D及D-1使用同一个H。
- 明示：经营日可能来自历史模拟数据，并不自动等于昨天。首版只做当前空间全量口径，不加平台/SKU/国家筛选，避免汇总预警与明细过滤错配。
- 标注“按当前有效数据版本重算”，不是还原历史当天已知的信息。H只影响现有退款观察口径，不是全量数据库的历史截断条件。

### 2. 经营概览

| 指标 | 展示 | 限制 |
| --- | --- | --- |
| 折后销售额 | D日、D-1日、相对变化 | 缺日不填0 |
| 有效完成订单数 | 两日笔数、增减笔数 | 无有效样本时同时显示数据状态，0笔不证明账本收齐 |
| 商品毛利 | 两日金额、金额差 | 仅成本已知样本；同时显示两日成本覆盖率 |
| 暂估贡献利润 | 两日金额、金额差 | 非净利润；未知费用不补0，保留现有限制 |
| 广告归因ROAS | 两日倍数、倍数差 | 不解释为整体盈利 |
| 12天退款订单率 | 两日订单队列的比例、百分点差 | 刚结束日期通常尚未成熟，应显示无法评估及原因，不改成当日退款率 |

补充显示有效完成订单数、成本已知样本数、成本覆盖率、订单可用率、成熟退款样本数和现有limits。确认退款金额可作为辅助指标，明确按退款确认日计量，与订单队列退款率不同。

比较边界：严格D对D-1，不寻找“最近有数据的上一天”；任一天不可计算则不生成变化结论；销售基期为0不计算增长率；利润使用绝对金额差，避免亏损基期产生反直觉百分比；比例变化用百分点，ROAS变化用倍数。只描述观察结果，不生成因果归因。若利润覆盖不完整，差额必须标注“仅可计算样本，不代表全部订单利润变化”。

### 3. 已记录规则证据

标题使用“观测期截至D日的历史预警证据”，不使用“今日检测发现”。

- 从当前空间的alert_detections读取证据，以evidence_json.period.end等于D过滤；不以检测创建日期充当经营日期。
- 同规则版本、同对象、同观测窗口多次触发，仅展示最后一条已保存触发证据（created_at、id确定顺序）。这是最新触发证据，不等同于最新一次检测结果。
- 展示对象、规则快照名称/版本、指标值、阈值、观测期起止、检测参考日、证据保存时间及来源。
- 关联alerts的处理状态只标作“当前处理状态”，不能声称是D日当时状态；不使用alerts初始period字段替代每次检测证据中的实际窗口。
- 历史触发证据可能后来不再触发，明确写“历史触发，不代表当前仍触发”；不能仅凭current_triggered或没有新触发记录判断历史检测是否全面完成。
- 没有匹配证据显示“暂无截至该日的已保存触发证据，不能据此认定无异常”；空间无任何检测证据时提示“未找到检测证据，请前往智能预警查看或手动运行检测”。不伪造13条规则全部正常的结论。
- 已解决但有触发证据不合并为一个状态：保留“历史触发证据”和“当前已解决”两列，不自动重新打开待办。
- 明示经营指标使用当前数据重算，预警证据是当时版本快照；修订后两者可能不同，不覆盖历史证据。

### 4. 规则模板建议

只根据展示中的证据类别给出检查动作，优先引用证据已有checklist。附对象、规则版本及窗口；称“建议核查”，不声称诊断成立或已经处理。

| 证据类别 | 示例建议 |
| --- | --- |
| 库存不足/覆盖不足 | 检查证据中的库存快照日期、补货周期和在途信息；不推算未提供的在途数量 |
| 广告效率异常 | 核查广告账单、归因口径与商品组合；不直接要求增加预算 |
| 毛利/贡献下降、成本异常 | 先检查成本覆盖率、成本修订和费用完整性，再核对活动与账单 |
| 退款异常 | 核查成熟观察窗口、批准退款及售后凭证，不把未成熟订单当零退款 |
| 无匹配证据 | 提示查看检测参考日及证据范围，不生成库存/广告异常结论 |

同对象同规则窗口去重建议；已解决/已忽略项标注当前处理状态，建议作为复核参考，不算新待办。建议是模拟规则模板，不是AI生成。

### 5. 下载日报

可离线HTML，包括范围、数据版本说明、两日指标、比较文案、质量限制、证据、建议及生成时间；导出与页面使用同一组已计算结果。原始文本转义，不嵌入执行脚本。不记录“已送达”，不发送邮件，不新增日报数据表。若需要固定历史日报，以下载文件保存；未来数据库快照需另行设计。

## 验收标准

1. 同空间同日期同H的日报指标与MetricCenter.calculate逐字段一致；查看及下载前后records、anomalies、alerts、alert_detections、reviews、record_revisions均不变。
2. 空库、日期无匹配、隔离样本、缺少前一天、销售零基期、利润负数、未知成本均有明确显示，不作错误增长结论。
3. D日退款观察未满12天时显示未成熟/不可评估；不能用0替代None。H变化与指标服务结果一致。
4. 历史检测窗口与D不匹配不纳入日报；同窗口多次触发正确去重；规则版本不同不合并；不把已解决解释为未曾触发。
5. 缺少检测证据不显示“全部正常”；日报不运行规则检测，不生成待办；只展示快照支持的信息。
6. 页面与HTML范围、数值、状态、建议一致；危险原始文本按文字呈现；不同空间证据与筛选不串用。
7. 全量pytest及独立模拟数据库真实浏览器通过，保留日期、样本、证据窗口和空状态截图。

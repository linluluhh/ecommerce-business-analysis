# 面试业务案例：从错误订单识别到经营日报修正

> 个人技术作品集，全部为Synthetic合成模拟数据。案例数字来自2026-10-26 Playwright + Microsoft Edge公开网址实操，不代表真实企业收益。以下“我”可作为作者讲解稿；项目使用Codex辅助开发，应如实说明自己的业务定义、实现核查和验证工作。

[在线演示](https://ecommerce-business-analysis-izcmrhydxddnasxqdbdxxr.streamlit.app/) · [首页](../../README.md) · [视频分镜](VIDEO_SCRIPT.md) · [展示证据](SHOWCASE.md)

## 1. 项目背景：运营每天究竟在做什么

跨境电商的订单、采购成本、库存、退款和广告通常来自不同文件。运营人员要统一SKU和日期、匹配成本、排除重复与错误，再做透视表和日报。一个未知成本被填成0，就可能把收入误当利润；直接改单元格，又会使昨天和今天的报表无法解释。

我的目标是把“发现异常—确认来源—核查处理—更新有效版本—重新汇报”连接起来。系统不负责替人判定退款根因或决定采购，而是减少重复核算，留下核查依据。

## 3. 复现前提

1. 打开公开网址，等待Synthetic独立会话加载。请勿输入真实个人、业务或凭证信息。
2. 如已修改过样例，点击“重置我的演示”。此操作只针对自己的临时演示。
3. 全期分析使用2026-09-01至09-14，平台/SKU/国家/状态全部。本案例经营分析H=2026-10-26；日报与预警参考日按下文设为2026-10-21。两种H在本样例相关队列都已成熟，仍应明确披露。
4. 下列ID是本次实测值。会话、批次和异常ID可能变化，复现时优先按订单号和业务描述定位，不强行使用固定编号。
5. 日期使用页面可见的年月日控件，修改后等待正文中的范围同步，再下载。不要通过隐藏日期字段替代可见操作。

## 4. 完整业务操作案例

### 第一步：建立初始经营基线

进入“数据运营工作台”：有效订单71笔，销售1364 USD，毛利658 USD，暂估贡献262 USD；待核实异常3条，受影响记录2条。

切换“质量检查”：金额与数量检查2条，指向同一负价订单；主数据与关联1条，指向另一张未知成本订单。异常数、受影响记录数和损失金额不是一个概念。

### 第二步：定位SYNTH-BAD

在“查看质量问题及处理建议”选择单价问题，展开“所选问题的原始值与技术证据”。

- 订单：SYNTH-BAD；平台Amazon；SKU001；订单日2026-09-14。
- 本次记录ID72，源文件Synthetic.xlsx第73行。
- quantity=1、unit_price=-10、discount=0。
- invalid_price：单价不大于0，硬性整行隔离。
- invalid_discount：优惠超过数量×单价；负单价连带导致金额关系不合法。

系统知道数据不合法，但不知道正确单价是多少。不能把“确认异常”说成“已修复”，也不能通过驳回硬错误直接放行。

### 第三步：解释SYNTH-UNKNOWN

选择标准SKU不存在的问题，查看SYNTH-UNKNOWN、SKU999，本次记录ID71，源文件第72行。单价20、数量1，收入有效；商品主表没有成本，收入20 USD保留，利润不可计算。

全期成本已知收入1344 USD，总销售1364 USD，成本覆盖率98.53%；658 USD毛利只属于已知成本样本。不能把未知成本填0，也不能说98.61%的订单可用率等于账本已收齐。

### 第四步：做SKU对比

进入“经营分析”，保持9月1日至14日，先选SKU001，再选SKU002：

|SKU|销售USD|订单|毛利USD|毛利率|贡献USD|说明|
|---|---:|---:|---:|---:|---:|---|
|SKU001|924|49|532|57.58%|178|全期退款订单率12.24%，需核查|
|SKU002|420|21|126|30.00%|数据不足|广告费用/归因数据不足，不能当成0|

平台下拉实际只有Amazon，因此本次没有多平台对比证据。讲解结束后把SKU恢复“全部”，避免把单SKU指标当全期基线。

### 第五步：识别退款风险并记录处理

进入“智能预警”，检测参考日设2026-10-21，点击“运行规则检测”。本次返回触发22项、新增0待办，因为初始化已保存同周期待办。

选择“平台退款订单率上升 / Amazon”：

- 前期2026-09-01至09-07：2.38%。
- 本期2026-09-08至09-14：17.86%。
- 上升15.48个百分点，阈值5个百分点，窗口7天。

选择“处理中”，填写模拟说明，例如“核对退款批准凭证、成熟订单队列及商品和物流原因；尚未确认根因”，保存后查看日志。

这只是调查方向。不能直接认定商品质量差，也不能把平台、公司和SKU层面的相关预警当成互不相关的22个问题。

### 第六步：申请并批准模拟修订

进入“数据修订”：

1. 搜索“修订原始记录”中的SYNTH-BAD。
2. “允许修订字段”选择unit_price。
3. 新值20；原因注明“仅Synthetic模拟，按模拟凭证核对负单价”。
4. 凭证引用填写SYNTH-PORTFOLIO-PRICE20，不填真实路径或真实凭证。
5. 提交申请，查看“审批前指标不变”。
6. 审核结论选“已批准”，填写模拟审核说明，保存审批。
7. 展开原值、新值、凭证和审批历史；当前有效值与修订链显示批准后的20。

当前演示允许同一访客申请、审批。操作员是自报标识，不是已经实现生产职责分离；凭证引用也不是自动验真。

### 第七步：对账指标重算

回到“经营分析”，再次核对日期和全部维度，不能假定导航后保留原筛选。

|指标|修订前|修订后|解释|
|---|---:|---:|---|
|销售USD|1364|1384|增加20；原-10订单原本被隔离，不是增加30|
|有效订单|71|72|新增一张有效完成订单|
|商品毛利USD|658|670|增加12，只覆盖已知成本样本|
|暂估贡献USD|262|272|增加10，继续扣除相应已记录费用|

修订不是“制造20美元新业务”，只是让原先被隔离的模拟订单按有效版本进入统计。

### 第八步：不要漏掉关联库存差异

回到工作台质量检查，选择“库存出库数量与有效完成订单数量不符”。本次新异常4，库存记录101，源文件第28行，SKU001、2026-09-14：期初23、入库0、出库2、期末21。

修复后订单样本改变，库存出库记录仍为2，所以出现跨表一致性差异。系统没有证明仓库错发或漏记；需人工核查订单履约、库存口径及凭证。本次不为了让页面“全绿”而强行修订库存。

批准后重新质检，当前质量问题变为未知成本和库存一致性两类；订单可用率100%仍不代表没有其他问题。经营预警需另外运行检测；视频保留修订前预警作为历史证据，不冒充修订后检测结果。

### 第九步：生成修正日报

进入“经营日报”，D=2026-09-14、H=2026-10-21，核对正文后点击“下载HTML日报”。日报不继承经营分析中的SKU筛选，而是当前空间全部平台、SKU和国家。

|日报KPI|修订前D|修订后D|D−1（9月13日）|
|---|---:|---:|---:|
|销售USD|92|112|72|
|有效订单|5|6|4|
|商品毛利USD|28|40|28|
|暂估贡献USD|-8|2|-8|
|广告ROAS|0.56|0.56|0.56|
|12天退款订单率|0%|0%|0%|

修订前销售增长27.78%，利润却没有增长：新增收入中有未知成本订单。修订后销售较前日增长55.56%，其中包含数据纠错的影响，不能解释成当天经营动作带来的增量。

下载HTML在离线Edge中可以打开。报告包含样本范围、限制、历史预警和核查建议；暂估贡献不是财务净利润。

## 5. 必须讲清的指标口径

- 销售额：Σ(数量×单价−整单优惠)，只纳入有效completed订单，含未知成本收入。
- 商品毛利：成本已知收入−对应商品采购成本；不扣物流、佣金、退款和广告。
- 毛利率：毛利÷成本已知收入。初始658÷1344≈48.96%，不是658÷1364。
- 暂估贡献：毛利−物流−佣金−确认退款−已记录广告，非净利润，费用缺失不能擅自填0。
- ROAS：同广告样本的归因收入÷花费，不能把广告归因收入再次加进订单销售额。
- 12天退款订单率：成熟的成本已知有效订单中，下单后0—12天有有效批准退款的不同订单占比。退款费用按确认日计量，不能与队列退款率混用。
- D严格比较前一自然日D−1；H只影响退款观察队列，不是所有业务数据的历史截断日期。
- 全期SKU001退款率12.24%与后七天35.71%属于不同窗口，不能混为一谈。

## 6. 最值得展示的三个技术难点

### 难点一：异常隔离不等于删除数据

保留原始行、业务键、批次与source_row，另存异常和审核状态。指标读取有效事实，而非直接把所有原始行相加。整行隔离与仅利润隔离分开，避免把未知成本当0。技术证据：[Store](../../v2/service.py)、[质量展示](../../v2/quality_presentation.py)、[指标事实](../../v2/metrics.py)。

### 难点二：多个页面必须使用同一指标口径

经营分析、预警与日报复用MetricCenter；日报组装D和D−1，并将同一份展示数据交给HTML导出，导出不重新运行检测或审批。它降低页面和下载文件各算一套公式的风险，但仍需核对筛选、样本与时间范围。技术证据：[指标](../../v2/metrics.py)、[日报](../../v2/daily_report.py)、[导出](../../v2/daily_report_export.py)。

### 难点三：修订要防止无痕覆盖和旧版本覆盖新版本

申请保存original_json、changes_json、凭证引用和base_hash；有效版本按批准修订叠加，原始记录不覆盖。审批用事务，检查申请基于的版本是否仍匹配；批准后重新质检，非法新值仍不能直接进入指标。技术证据：[Revisions.request/decide与effective_rows](../../v2/revisions.py)。这不是防篡改审计或生产级身份认证。

## 7. 企业真正使用前还需什么

|改进方向|业务原因|
|---|---|
|真实平台字段适配与同步|平台导出字段、状态、时间与退款口径需要映射和核对|
|订单行、多SKU与多币种|目前单SKU/USD不能覆盖真实混合订单及币种转换|
|历史成本与完整费用|需要成本生效日、仓储、税费、汇兑等，不能用当前静态成本重写历史利润|
|身份权限、职责分离|申请人与审批人要有可靠身份和权限控制|
|持久化、备份与恢复|公开临时会话不能承载业务台账；本地文件与数据库需一致备份和恢复演练|
|数据完整性与财务对账|可用率高不意味着账本收齐，要检查日期、平台、批次和账单总额|

这些是后续方向，不是本作品已实现能力。小批量单企业辅助分析可作为试点定位，未测过生产吞吐量和多人并发，不能承诺容量。

## 8. 90秒口述版本

我做的是一个面向跨境电商数据运营的个人作品集，使用模拟数据，重点是把质量检查、经营分析和修订后的日报连起来。

演示里有一张SYNTH-BAD订单，单价是负十美元。系统保留原始记录和来源行，但先把它隔离，避免错误金额进入统计。另一张订单收入二十美元，却找不到商品成本，我保留它的收入，不把成本填零来虚增利润。

核对模拟凭证后，我把负价订单申请改为二十美元。申请时指标不变，批准后销售额从一千三百六十四变成一千三百八十四美元，暂估贡献增加十美元。系统还重新发现库存出库和订单数量不一致，所以修订单价并不意味着所有问题都解决了。

技术上，我用Python和Pandas处理数据，用SQL和SQLite保留来源、审批及版本，由统一指标服务驱动分析、预警和日报，Streamlit提供操作界面。

这个项目展示的是指标口径、异常核查和可追溯处理能力。它还没有真实平台同步、生产权限和完整财务成本，因此我把它定位为运营辅助作品，而不是生产级财务系统。

## 9. 面试追问的简短回答

- **为什么不是涨30美元？** 原负价行被隔离，修订后新增的是20美元有效收入。
- **为什么收入增长、利润没变？** 初始日报新增的20美元收入缺成本，不进入已知利润样本。
- **退款预警意味着什么？** 同口径窗口越过阈值，值得调查，不证明根因。
- **为什么批准后还有异常？** 重评发现与库存的跨表差异，不能仅把表单审批当数据正确。
- **为什么日报与历史预警可能不同？** 日报按当前有效版本重算，预警保留触发时的版本；需重新检测。
- **是否验证了188项测试？** 2026-10-22原始记录为188 passed；本次展示整理未重跑，2026-10-26另有线上业务实操证据。
- **代码是否全部独立手写？** 使用Codex辅助开发，应清楚说明自己负责的业务设计、代码核查和验证工作，不夸大独立编写比例。
